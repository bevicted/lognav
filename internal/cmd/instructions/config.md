# Configuration instructions

Use this topic when the user asks to inspect or change lognav configuration.

1. If the request could refer to multiple behaviors or fields and existing terminal output does not disambiguate it, ask what should change before running a configuration command. Otherwise use existing terminal output as evidence. Public built-ins, optional read-only Homebrew defaults, optional `system.yaml`, and `user.yaml` merge in that order. `icl.instances` is the writable user override list of target records with `name` and `crn`; omission inherits, while `[]` intentionally clears all targets. For valid configuration, inspect the narrowest relevant field with `lognav config describe <dotted-key>` or `lognav config get <dotted-key>`; use `lognav config show` only for a necessary full effective view. If invalid configuration blocks those reads, inspect the supported schema with `lognav --no-config config describe <dotted-key>`.
2. If the request is inspection-only, answer from that evidence and stop. For a clear requested change, proceed without redundant confirmation.
3. Resolve the editable `user.yaml` file with `lognav config path`; it is never the read-only Homebrew defaults or `system.yaml`. Preserve its exact prior bytes locally, or record that it did not exist, before editing. Edit that sparse YAML directly and change only the requested overrides. Do not run Git commands or commit the resolved config unless the user explicitly identifies it as repository-managed. Never print API key, access-token, or refresh-token values; leave credential installation to the user.
4. Validate with `lognav config show -o json`, redirecting broad output locally when it is not needed as evidence. Verify the requested effective value or state, not merely that a default-populated field exists. Keep secret comparisons local. If validation or the effective-state check fails, restore the exact prior bytes; if the file did not exist before the edit, remove the new file. Report the error after restoration.
5. Complete only when validation succeeds and the effective output reflects the requested change. For field detail, use the narrowest applicable `lognav config describe <dotted-key>` command.
